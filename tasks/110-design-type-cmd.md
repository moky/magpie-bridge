# Magpie Bridge Protocol

本文档定义协议头标志位含义、内部关系，以及通用指令和应答机制。


## 协议头

协议头第 5 字节（偏移量 4）为类型 Type。


## 类型 Type （1 字节）

高4位用作标志位，低4位用作分包参数变量长度：
    
      0   1   2   3   4   5   6   7
    +---+---+---+---+---+---+---+---+
    | A | B | C | D |               |
    | C | I | M | S |      LEN      |
    | K | D | D | N |               |
    +---+---+---+---+---+---+---+---+

### 标志位解析

- **A=1** 表示是应答包（数据应答 COPY 必须 D=1；系统指令应答 SYN!/ACK!/PONG/FIN! 为 D=0）；
- **B=1** 表示服务器桥接包（包括与服务器握手、要求转发），代表包头中包含两个 4 字节整数，依次为 target 和 source (Bridge ID，门牌号)；
- **C=1** 表示包头含有 command 指令信息 (4 bytes)；
- **D=1** 表示包头含有 DSN 数据序列号 (4 bytes) 以及可能的分包参数 （index, count)，其中 count 是分包总数，index 是当前子包序号 (0 <= index < count)；D=1 仅用于普通数据包及其数据应答 COPY（需要 dsn 配对确认），系统指令（SYN?/SYN!/ACK!/PING/PONG/FIN?/FIN!）一律 D=0；
- **E**: 整数，表示分包参数 (index, count) 变量的长度，取值范围如下：
	- 0: 无参数（无需分包的微型数据包，相当于 index=0, count=1）
	- 1: 参数长度为 1 字节（2 <= count < 256)
	- 2: 参数长度为 2 字节 (256 <= count < 65,536)
	- 4: 参数长度为 4 字节 (65,536 <= count < 4,294,967,296)

E 的其余取值（3、5~15）未定义，收到此类包直接判定为错误包。

因此，分包参数长度 E 对应 4 种规格的消息/文件包，分别是：

1. mini 消息包 (<= 1024 bytes)
2. 小文件 (1024 B ~ 255 KiB)
3. 普通文件 (255 KiB ~ 64 MiB)
4. 超大文件 (64 MiB ~ 4096 GiB)

注：以上按二进制单位（KiB/MiB/GiB）计，均为约数（精确值 = count 上限 × 1024）：
255 KiB = 261,120 B（255×1024）；64 MiB ≈ 67,107,840 B（65535×1024；精确 = 64 MiB − 1 KiB）；
4096 GiB ≈ 4,398,046,511,104 B（(2^32-1)×1024；精确 = 4096 GiB − 1 KiB）。

### 内部关系

1. 数据应答包（COPY，A=1, D=1）必定携带 dsn（及可能的 index, count），用于与原始数据包配对确认；系统指令应答（SYN!/ACK!/PONG/FIN!，A=1, D=0）无需 dsn；
2. 如果 B=0，则表示是客户端直连的数据包，中间不经过服务器，所以包头不含 bid 字段（target/source 字段不存在）；
3. 如果 C=1，则此包头部含有 command 信息（4字节），通常用作额外参数（具体值在后面定义）；
4. 如果 D=1，则表示该数据包存在 dsn 以及可能的 index, count（由 E 决定）；客户端收到 D=1 且 A=0 的普通数据包时需要回复数据应答 COPY；
5. 如果 E>0，则必定 D=1，因为需要分片的数据包一定有序列号，此时 dsn+index 才是该类型数据子包的唯一标识。


## Command

如果标志位 C=1，则协议头末尾 4 字节为 command 信息：

| Value | Flags                    | Desc                        |
|-------|--------------------------|-----------------------------|
| SYN?  | A=0, C=1, D=0, E=0       | 第1次握手                    |
| SYN!  | A=1, C=1, D=0, E=0       | 第2次握手（应答）             |
| ACK!  | A=1, C=1, D=0, E=0       | 第3次握手（成功连接）          |
| DATA  | A=0,      D=1            | 普通数据包（可选，C 可 0 可 1） |
| COPY  | A=1, C=1, D=1            | 确认收到（数据应答包）         |
| PING  | A=0, C=1, D=0, E=0       | 发起心跳                     |
| PONG  | A=1, C=1, D=0, E=0       | 心跳应答                     |
| FIN?  | A=0, C=1, D=0, E=0       | 第1次挥手                    |
| FIN!  | A=1, C=1, D=0, E=0       | 第2次挥手（应答）             |
| -     | -                        |                            |
| NOOP  | -                        |                            |
| USER  | -                        | 用户自定义                   |

> 注：系统指令（SYN?/SYN!/ACK!/PING/PONG/FIN?/FIN!）均为 D=0，不携带 dsn，发送方无需维护等待应答的队列；
> 仅普通数据包及其数据应答 COPY 使用 D=1（需要 dsn 配对确认）。因此 **D 位可直接作为"发送后是否需要等待应答"的判据**。

1. 所有数据包都可选择是否通过服务器转发，所以 B 可以是 1 也可以是 0；
2. 普通数据包可以选择 A=0, C=0, D=1 的方式发送，即不需要 command 字段，接收方收到后依然需要回复应答包 "COPY"（A=1, C=1, D=1）；
3. 如果 C=1，则 command 必须是上表已定义的值之一，否则判定为错误包。
